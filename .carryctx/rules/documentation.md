# Documentation rules

1. English is the only canonical documentation language. Translations, locale
   directories, and multilingual routing remain deferred.
2. `bitty-docs` owns plugin architecture, API, security, package, compatibility,
   decision, and public-behavior contracts. This repository owns template and
   generated-output evidence plus repository-local contributor guidance.
3. Distinguish normative, accepted, candidate, open, implemented, and verified
   statements. A proposed tree or example is not evidence of a usable scaffold.
4. Keep template contributor instructions separate from generated plugin-author
   guidance, and label their audience explicitly.
5. Generated instructions and examples are minimal, safe, version-aware,
   capability-aware, and tested from a clean scaffold.
6. Document placeholders, generated-file ownership, update strategy, supported
   versions, failures, cleanup, compatibility, and security impact.
7. Preserve provenance and inspected revisions for generated-output and
   compatibility claims.
8. A public scaffold change must update canonical `bitty-docs` in a linked
   change before completion.
9. Validate language, links, formatting, clean generation, repository hygiene,
   and factual status before review.
